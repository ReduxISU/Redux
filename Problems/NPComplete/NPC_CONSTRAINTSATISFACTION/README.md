# Constraint satisfaction solver and verifier

The existing `(X,D,C)` instance representation and `{(variable,value),...}` certificate format are preserved. Identifiers are case sensitive. Every variable must occur exactly once in a certificate and its value must belong to its domain. Malformed certificate syntax throws `CertificateParseException`; well-formed certificates with missing, duplicate, unknown, or out-of-domain assignments return false.

Each quoted constraint must contain exactly one comparison (`=`, `==`, `!=`, `<`, `<=`, `>`, `>=`). Its operands support decimal integer literals, variable identifiers, binary `+` and `-`, unary signs, and nested arithmetic parentheses. Examples: `x!=y`, `x+y-z<=3`, `-(x-y)=z`, `x+2147483648>y`. Integer arithmetic uses arbitrary precision, without overflow. All constraints must hold (conjunction).

Multiplication, division, modulo, exponentiation, functions such as `allDifferent`, Boolean operators, chained comparisons, and parentheses enclosing a complete comparison are unsupported. Unknown variables, malformed expressions, and unsupported syntax throw `ProblemParseException` when a solver or verifier compiles constraints. The problem constructor continues to preserve expression text; it does not compile expressions. Constraints are compiled before any search or certificate acceptance, so unsupported syntax cannot silently pass even on a branch that would otherwise be rejected early.

`ConstraintSatisfactionBruteForce` enumerates complete assignments without pruning. `ConstraintSatisfactionBacktracking` rejects partial assignments as soon as a constraint's effective variable scope is assigned. `ConstraintSatisfactionIntelligent` recomputes viable values for every unassigned variable after each assignment, detects domain wipeouts, and chooses the minimum remaining values variable (input order breaks ties). Forward checking prunes constraints with at most one variable still unassigned; higher-arity constraints are checked when enough variables are assigned. Recomputing candidates restores domains on backtracking. Search uses explicit stacks, avoiding recursion depth limits. The existing `ConstraintSatisfactionSolver` identifier delegates to the intelligent algorithm.

The verifier runs in polynomial time in the combined instance and certificate length: parsing and flattening expressions, domain membership checks, and arbitrary-precision sums do not enumerate assignments. The solvers are exact, with exponential worst-case search. They check Redux's cooperative timeout flag during compilation, candidate generation, and search; timeout returns `SolveRun.TimedOutAnswer`, never an unsatisfiability claim. Redux's `ISolver.Run` supplies/reset the timer. No solver resets a flag that has already expired.

Exhausted search returns `{}`, following Redux convention. For zero variables, `{}` is also the valid empty assignment when all constant constraints hold; the verifier distinguishes this case. For nonempty variables it is not a witness for unsatisfiability.
